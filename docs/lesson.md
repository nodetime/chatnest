# Lessons

## 2026-10-21：工具交互与产物展示

- 场景：用户反复指出工具列表和右侧产物不够自然。
- 我做错的：把压缩字号和留白当作完成设计；把表格需求扩大成整个右侧的表格工作台；理想化工具样本没有包含真实 SDK 空文本与元数据，漏掉了分组失效。
- 下次避免：先确认通用产物与专用能力的边界；在真实持久化消息上验证顺序、分组、审批和编辑，再做视觉验收。编译和单测通过只证明部分正确性，不证明设计已被用户认可。

## 2026-10-23：用实际浏览器审视布局与生命周期

- 完成样式不等于完成布局：重复的300px产物预览与右下悬浮竖条，在短代码场景尤其突兀。当前产物以72px文件卡指向右侧，辅助操作使用正常标题栏菜单。
- 产物状态不等于面板状态：artifact.isVisible不代表workspace.open/documenttab。卡片激活需要明确打开对应面板；只测样式正则会漏掉关闭重开。
- Tailwind预设的hrheight:0会让分隔条看似存在但没有实际命中高度。最终以浏览器实际rect900px、键盘60→65与实际拖动为准。


## 2026-10-23：模板必须转化为可用的结构与状态边界

- 用户说“参考模板”不是再改一遍色值：要验证真实上游源码和许可，将 Conversation、Task、Artifact、PromptInput 组合进现有状态边界，并交付标题、输入、文件导航等真正的交互变化。
- 新增文件选择器时，普通编辑器 dirty 不包含结果表格的 notes/view dirty；独立规格审查发现这一缺口后，传递表格既有 dirty/saving 的权威投影，并以实际浏览器编辑→禁切→保存→切换→恢复验证。不要发明第二套表格保存状态。
- 视口模拟会影响 GUI 点击与截图比例：本轮 1440 模拟下消息编辑点击未命中，恢复原尺寸后正常。先核对真实状态/坐标、实际 handler 链与标准视口，别按猜测改生产回调。
- 源码、单测和构建通过不代表用户已认可美观；交付真实截图与可操作页面，不宣称达到商业产品整体能力。


## 2026-10-23：先审视真实工具结果，再谈组件复用

- 用户具体指出 PDF 读取结果时，问题是“执行过程→工具→原文/技术”的层级与内部统计外泄，不是换一组颜色。实际进入 Manus 已有测试任务展开过程后，对照其低权重过程入口与轻量动作记录；没有发新任务或消耗积分，参考截图保持 ignored/private。
- 单步应是自然的文件动作，点开即可核对原文。技术参数仍需可查，但放独立详情；原文引用与警告不因界面精简而丢失，运行时不可信资料边界也不改。
- 局部 Group→Sheet 测试通过，仍可能漏掉上层渲染换型。两次真实5秒HTTP MCP完成验收均复现 Sheet无操作消失；最终固定 canonical PreviewMessage 身份，再用同样现场证明详情存活、返回值实时更新、Esc回到可见原按钮。
- 原生表格从生成步骤交接正常产物，是不同生命周期：不要给临时非终态挂一个注定消失的检查入口；异常/历史与动态MCP则保持可追溯。单测数量不是用户认可美观的替代物。

## 2026-10-23：统一工具交互不等于把 JSON 换成列表

- 主会话实际展开已完成搜索，发现空结果面板；初版泛型预览虽有内容，却展示 transport metadata、重复 structuredContent 树，仍是调试器。浏览器截图复核后改为真实标题/关联来源/少量原始字段，技能简述和参考原文各有明确层级。
- “简化”必须诚实：独立规格审查复现丢弃同级警告却未提示部分预览，以及正文旁误称整个结果为空；修正省略标记与字段级空列表，并保留原始详情。
- 390px 实际截图发现短动作名反被截断；仅保护可信短动作，先压缩主体文本，长未知 alias/技能名仍可收缩。屏幕可用性不能只靠 overflow=false 判断。

## 2026-10-23：阅读结果和检查原始字段必须分层

- 将 JSON 改成带原始 key/value 的结果卡片，仍是调试界面。普通结果只展示实际标题、摘要、来源；其余字段进入详情，审批参数另行保留，不能为了美观隐去审批含义。
- 摘要缺失就不编造；snippet-only 与空白文本均应有真实可读呈现或明确详情入口。纯结构化结果的两条“看详情”提示也是冗余，需要实际浏览器核对。
- 通用产物中的用户选择列不等于工具预览字段。保留原表格数据/筛选/备注/导出，改善双栏比例和链接标签，不把所有结果强行变成表格。

## 2026-10-27 正式工作台落地

- Figma 能点通不是应用验收；必须用真实认证、PG、文件解析和SDK工具续跑验证。外部模型/MCP使用本地夹具时明确标注，不冒充真实供应商结果。
- raw postgres 与 Drizzle 命名约定不同：只定义 camelCase TS 类型不会转换SQL列。上传曾成功而后续owner判断404，需从注册、读取、消息绑定一直走到刷新恢复；只转换列名，禁止顺手改原始JSON字段。
- SidebarMenuButton 的 data-active 样式可覆盖主按钮文字，icon尺寸会裁切带标签菜单；组件复用必须实际检查计算颜色与触控/文字尺寸。
- 客户端 addToolOutput resolve 只表示本地消息已改，不代表服务端已保存；Ask答案先在最新属主消息上原子合并，再续跑。停止先关自动续跑门，旧Chat实例回调也要失效。

## 2026-10-27：个人能力隔离与动态表单

- 验收用脚本模型不得绑定用户日常预览端口。验收单独端口、数据库及构建目录，明确标记夹具；普通预览沿用用户私密模型配置，不将固定测试题目当成 Agent 产品行为。
- 关闭技能不仅要过滤工具目录：历史 loadSkill/readSkillResource 正文也可能重新进入模型上下文。按本轮范围投影历史，并保留原始存储证据；同 ID 编辑不能让旧指令冒充新版本。
- 个人数据摘要的客户端缓存必须绑定用户；服务端属主鉴权与加密不替代客户端缓存隔离。
- 每次外发前复验当前授权版本；旧审批同时绑定存储消息、连接修订和任务范围代次。重复审批通过真库行锁/CAS验收，不仅测前端禁用按钮。

## 2026-10-27：失败交互做减法

- 失败标记需要持久化，不等于需要另造“让 Agent 继续处理”按钮和固定用户指令。
- 同一次失败只展示一个简短状态；原始错误留在按需详情，不同时堆消息提示、恢复卡片、输入框告警和 toast。
- 继续输入走正常聊天；工具审批、Ask 回答、明确的步数预算暂停仍保留各自语义，不借失败恢复重放工具。

## 2026-10-27：Agent 状态需要贯穿工具与产物

- SDK 中止可以正常 resolve；`addToolOutput` 也只更新本地。Ask 不根据 Promise resolve 假定保存，异常时用属主端只读快照核对精确答案。
- 所有产物入口都要遵守未保存保护，仅给顶部选择器加门控仍会丢草稿。
- 统一工具 UI 时同时统一原生业务错误契约；不能把 `{error}` 误标完成，也不能把第三方 MCP 的普通同名字段擅自解释为失败。
- “默认折叠”不能在新增步骤时偷偷展开；用户主动打开的内容也不要在完成时突然收走。

## 2026-10-28：未登录是入口状态，不是管理空页面

- guest 技术会话不代表用户已登录；正式个人入口应直接进入登录，不展示一套禁用操作和“登录后可以…”说明。
- 前端守卫、直达链接、设置内嵌入口都需覆盖；后端认证与属主校验继续独立生效。
- 登录回跳既要保留目标，也要拒绝站外地址；跨账号后重建个人编辑器，避免旧草稿留在新身份下。
- 真实浏览器验证密码错误可见、纠正后成功以及目标页重开；认证布局没有聊天的 Toaster，不能把调用 toast 当成已展示错误。
