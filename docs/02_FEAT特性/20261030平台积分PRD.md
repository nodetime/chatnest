# 平台账户、权益与工具积分 PRD

## 1. 问题与机会

数知探AI 已经具备通用 Agent、个人能力、MCP 审批和 Porta 工具执行，但账户权限、用户积分和工具调用账务尚未形成产品闭环。当前用户无法知道自己拥有的能力、余额、每次任务的消耗和异常调用如何处理；运营也无法安全地发放、扣减、补偿和审计积分。

## 2. 目标

### 产品目标

1. 正式 connected 部署使用统一平台账户、角色、权益和积分。
2. 每次实际 Porta 工具出站调用可被唯一识别、授权、记录和结算。
3. 余额不足、账户停用、平台故障和调用不确定时有明确行为，不产生隐式免费旁路。
4. 用户只看到简单余额和使用记录，不需要理解冻结、outbox 或供应商成本细节。

### 成功指标

| 指标 | 目标 |
|---|---|
| 重复扣分 | 同一 operation/attempt 绝不重复入账 |
| 并发超扣 | 账面余额始终不低于冻结积分 |
| 未授权出站 | 无有效权限或 permit 时供应商调用数为 0 |
| 结果未知 | 100% 进入可恢复待核对，不自动判免费 |
| 账务恢复 | reserve/dispatch/report 响应丢失可用同键查询恢复 |
| 价格生效 | 平台价格修改只影响新 operation |
| 体验 | 用户能看到余额、工具/模型使用记录和明确错误 |

## 3. 用户与场景

### 用户角色

- 普通用户：登录、使用允许的模型/工具、查看本人余额和账单。
- 运营人员：管理账户状态、权益、价格、发放、补偿和审计。
- 系统服务：ChatNest、Porta、结算 worker。

### 核心用户故事

- 作为用户，我希望在调用工具前知道是否有可用积分。
- 作为用户，我希望工具调用结果和余额变化一致，不因刷新重复扣分。
- 作为用户，当平台暂时不可用时，我希望看到明确提示，而不是被静默切换到无限额度。
- 作为运营人员，我希望按版本调整工具价格，不改写历史账本。
- 作为运营人员，我希望对未知结果进行核对和补偿，并保留审计理由。

## 4. 用户体验

### 用户端

- 账户页显示：可用积分、最近更新时间、简明使用记录。
- 任务/消息工具活动可显示“本次工具调用已计入使用记录”，不显示内部 permit/冻结状态机。
- 余额不足：提示需要补充积分或联系管理员，不继续调用。
- 平台暂不可用：提示当前服务暂不可用，保留任务输入，不自动重试工具。
- 未知结果：工具结果可保留，但账务状态显示“正在核对”，不显示已完成扣费。

### 管理端

- 账户状态、角色和权益。
- 工具价格、版本、收费模式。
- 积分发放、补偿、人工结案。
- operation、receipt、审计记录查询。

## 5. 功能需求

### FR-01 账户与权限

- 平台账户是 connected 模式的认证来源。
- ChatNest 为每个外部主体维护稳定本地 actor 映射。
- 权限必须同时满足账号有效、资源属主、能力范围、审批和可用积分。
- 停用、退出或权限版本变化后，新的工具调用必须被拒绝。

### FR-02 工具价格

- 每个工具使用 canonical `provider/platform/api` 标识。
- 价格包含 points、unit、chargeMode、version。
- 价格修改不回写历史 operation。
- 未配置价格的业务工具在 connected 模式默认拒绝。

### FR-03 积分预留与结算

- reserve 原子检查余额并创建 hold。
- dispatch 只消费已有 hold，不重复要求可用余额。
- report 按 receipt 和 chargeMode capture/release/reconcile。
- 所有写操作支持幂等键。

### FR-04 Porta 工具调用

- Porta 工具真实出站前必须完成平台准入。
- Porta 在统一 AOP 中写 pending 和完成 receipt。
- 相同 attempt 不重复调用供应商。
- 工具发现和 metadata 不扣用户积分。

### FR-05 异常恢复

- reserve/dispatch/report 响应丢失时可查询恢复。
- 超时、取消、崩溃进入待核对。
- 结算失败不丢弃已经获得的业务结果。
- 供应商调用不做隐式业务重试。

## 6. 范围边界

### 本期范围

- connected 账户和权限协议；
- 用户积分钱包和账本；
- 模型/Porta 工具 operation；
- Porta permit/receipt；
- ChatNest 统一 AOP；
- 环境变量种子配置；
- 管理员发放、补偿和核对。

### 本期不做

- 支付、订阅续费、邀请返利；
- 积分到期、周期清零、积分批次；
- 团队钱包和复杂多租户；
- 自动后台任务和通知；
- 供应商账单代付或供应商成本转售规则；
- 旧账号和旧业务数据迁移。

## 7. 依赖与风险

- Payload 业务应用仓库尚未进入当前工作区，需要先确定仓库和部署边界。
- Porta 现有 points metadata 测试需要在正式接入客户积分时重新定义边界。
- 连接断开和供应商异步结果不能用简单 HTTP 成功/失败判断。
- 真实供应商价格和真实扣费仍需独立验收，合成上游不能替代。

## 8. 里程碑

1. 协议与账务状态机评审。
2. Payload 平台基础账户/账务模块。
3. ChatNest 身份映射与 ExecutionGate。
4. Porta permit/receipt AOP。
5. 三方故障、幂等、并发和浏览器验收。
6. connected 灰度，不开放未定价工具。
