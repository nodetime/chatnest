# 平台积分需求与验收标准

## 需求清单

| ID | 需求 | 优先级 | 验收方式 |
|---|---|---:|---|
| REQ-01 | connected 模式只能使用平台验证过的账户主体 | P0 | API/浏览器 |
| REQ-02 | ChatNest 本地 actor 与平台 subject 一一映射 | P0 | 并发集成测试 |
| REQ-03 | 价格使用 canonical tool ID 和版本 | P0 | 单元/契约测试 |
| REQ-04 | reserve/dispatch/report 支持幂等 | P0 | 状态机测试 |
| REQ-05 | 每次 Porta 真实出站最多对应一个 attempt | P0 | 双进程测试 |
| REQ-06 | Porta 无 permit 时 required 模式不出站 | P0 | Porta 集成测试 |
| REQ-07 | 供应商成本账与平台积分账分离 | P0 | 数据边界测试 |
| REQ-08 | 超时/取消/崩溃进入待核对 | P0 | 故障注入 |
| REQ-09 | 价格修改不影响历史 operation | P1 | 回归测试 |
| REQ-10 | 用户可查看余额和简明使用记录 | P1 | 浏览器测试 |
| REQ-11 | 管理员可发放、补偿和人工结案 | P1 | 平台 API/后台测试 |
| REQ-12 | 统一 env 可解析、校验并拒绝非法价格 | P1 | env 单元测试 |

## Given / When / Then

### 正常流程

#### AC-01 余额充足的 Porta 工具调用

**Given** 用户账户有效、工具有已发布价格、余额足够且 ChatNest 已完成审批  
**When** Agent 发起一次 Porta 工具调用  
**Then** 平台创建一个 operation 和 hold，Porta 收到匹配 permit，供应商只收到一次请求，平台最终 capture 一次积分

#### AC-02 工具价格版本锁定

**Given** operation 已按价格版本 V1 reserve  
**When** 管理员发布 V2 价格并完成该 operation  
**Then** 该 operation 仍按 V1 结算，新 operation 才使用 V2

#### AC-03 使用记录展示

**Given** operation 已 settled  
**When** 用户打开账户使用记录  
**Then** 用户看到时间、任务、模型/工具类别和积分变化，不看到 token、permit、供应商 Key 或原始参数

### 权限与余额

#### AC-04 余额不足

**Given** 可用积分小于工具价格  
**When** Agent 请求调用 Porta 工具  
**Then** 平台返回 `INSUFFICIENT_CREDITS`，Porta 出站次数为 0，ChatNest 保留用户输入并显示明确提示

#### AC-05 账户停用

**Given** 用户账户已停用或权限版本已变更  
**When** ChatNest 尝试 reserve 或 dispatch  
**Then** 请求被拒绝，不使用旧缓存放行，不调用供应商

#### AC-06 未配置价格

**Given** connected 模式下工具没有明确价格  
**When** Agent 尝试调用该工具  
**Then** 请求被拒绝并记录未派发原因，不按 0 分执行

### 幂等与恢复

#### AC-07 reserve 响应丢失

**Given** 平台已成功创建 hold，但 ChatNest 未收到响应  
**When** ChatNest 用原 Idempotency-Key 查询或重试  
**Then** 平台返回原 operation，不创建第二个 hold

#### AC-08 dispatch 响应丢失

**Given** 平台已成功派发 permit，但 ChatNest 未收到响应  
**When** ChatNest 查询 operation  
**Then** 返回原派发结果，不重新派发，不重复调用供应商

#### AC-09 供应商调用超时

**Given** Porta 已进入 dispatching 并开始出站  
**When** 上游超时或连接断开  
**Then** operation 进入 `reconcile_pending`，不立即退款，不自动发起第二次供应商调用

#### AC-10 report 响应丢失

**Given** Porta 已生成 receipt，但平台 report 响应丢失  
**When** settlement outbox 使用相同幂等键重试  
**Then** 平台只完成一次 capture/release，最终状态可查询

### AOP 与 Porta

#### AC-11 统一切面覆盖静态和 Native MCP

**Given** 一个静态 provider 和一个 Native MCP provider 均已配置  
**When** 两种入口各执行一次业务调用  
**Then** 两者都经过同一类 around-call 账务切面，且各生成一个独立 attempt

#### AC-12 required 模式拒绝无 permit

**Given** Porta 处于 `PORTA_BILLING_MODE=required`  
**When** 调用方不带 permit 或 permit 与工具身份不匹配  
**Then** Porta 在供应商出站前返回权限错误，供应商调用计数为 0

#### AC-13 metadata 不扣分

**Given** ChatNest 请求 tools/list 或服务发现  
**When** Porta 完成 metadata 请求  
**Then** 只记录 metadata usage，不创建用户积分 operation

### 安全与隐私

#### AC-14 客户端不能伪造积分

**Given** 客户端提交伪造 points、userId 或 role  
**When** ChatNest 或平台处理请求  
**Then** 服务端忽略或拒绝伪造字段，价格和主体只来自可信服务端

#### AC-15 私密字段不泄露

**Given** 执行、失败、日志和账本均已产生  
**When** 检查 API、MCP 结果、日志、数据库和前端 payload  
**Then** 不包含服务 token、供应商 Key、原始参数、响应正文或 permit 签名密钥

### 非功能验收

#### AC-16 并发余额不透支

**Given** 两个进程同时竞争最后一笔可用积分  
**When** 两个 operation 并发 reserve  
**Then** 至多一个获得 hold，余额约束始终满足 `ledgerBalance >= frozen >= 0`

#### AC-17 单次派发门

**Given** 两个 ChatNest worker 同时处理同一 operation  
**When** 两者都收到相同 dispatch 结果  
**Then** 只有一个 worker 从 `ready` CAS 到 `sending` 并出站，另一个只能读取既有状态

#### AC-18 价格配置可校验

**Given** env JSON 包含负数、浮点 points、重复 tool key 或未知 chargeMode  
**When** 服务启动  
**Then** 配置解析失败，服务不进入 connected ready 状态

## 完成定义

- 所有 P0 需求和 AC-01 至 AC-18 通过。
- ChatNest、Porta、Payload 契约测试通过。
- 真实 PostgreSQL 并发账务测试通过。
- 真实浏览器验证登录、余额、调用、失败和使用记录。
- 合成供应商与真实供应商证据分开记录。
- 不以单元测试通过代替真实模型、真实 Porta 和真实账户验收。
