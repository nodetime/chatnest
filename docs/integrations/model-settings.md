# 模型配置

## 使用

1. 部署时完成数据库迁移、管理员 UUID 白名单和平台加密主密钥配置（复用 `MCP_SETTINGS_ENCRYPTION_KEY`，但模型与 MCP 使用独立加密域）。主密钥及数据库应一起安全备份；更换主密钥不等于自动迁移旧密文。
2. 管理员打开 `/admin/models`，填写 API 基础地址、该服务对应的 Key，选择 Chat Completions 或 Responses。
3. 手动填入供应商原始模型 ID，或点击“获取模型目录”；配置默认模型、工具与图片能力。目录出现某模型不代表账户具有调用权限。
4. “测试连接”只对默认模型发起短文本推理，可能产生小额费用；不会保存配置，也不代表文件/工具能力已验收。
5. 保存后新请求生效；当前生成继续使用自身快照。工作台只暴露已开放模型，不暴露地址或 Key。

## 安全与状态

| 项目 | 行为 |
|---|---|
| 旧环境配置 | 未保存后台配置时继续读取；不写 `.env`，不自动复制其他协议的凭据 |
| Key | 仅返回是否存在；加密入库；更换基础地址必须重新输入对应 Key |
| 并发编辑 | 版本冲突返回 409，保留输入；重新载入会放弃未保存草稿 |
| 模型状态 | 已配置、测试通过、完整任务通过是三种不同状态 |
| 401 / 403 | 检查凭据及权限 |
| 404 | 检查接口协议、基础地址与模型 ID |
| 429 | 检查限流或账户额度 |
| 5xx | 供应商/网关异常，不据此认定 Key 无效 |
| 代理 / 内网 DNS | 后台目的地仅允许公网 HTTPS；保留地址会在发送 Key 前被拒绝。部署方应提供正常公网解析；不为测试放开全局私网访问 |
| 目录不支持 | 直接填写原始模型 ID；目录与推理是独立检查 |

`MODEL_ALLOW_LOOPBACK_HTTP=1` 只在 development/test 下用于本地协议回归，不适用于生产。真实验收必须使用真正的模型服务；本地响应夹具仅用于单元测试。

## 验收边界（2026-10-24）

原先用户提及的 OpenAI 配置未在本项目、备份及关联克隆会话中找到；当前环境中的另一个网关未被视为原来的 OpenAI 凭据，也未自动迁入后台配置。本机 DNS 对当前网关返回保留的代理地址，新的连接保护明确拒绝该目标，未把它报告成 Key 无效。

后台实现与离线协议回归不等于真实模型任务通过。上传 → Agent 自主选用 Porta → 生成产物 → 重新打开的真实模型验收，仍需确认可用的地址、Key 和模型。Porta 的本地供应商样本也必须继续标注为合成数据。
