# Agent 材料与结果产物完善计划

**用户验收要求：** 以 Agent 为中心的应用，而不是脚本化业务流水线。模型选择工具/技能、迭代方式和可选交付物。运行时负责权限、有界执行、工具来源追踪、持久化和 UI。mock MCP/模型服务仅存在于已忽略的隔离验证夹具中，绝不作为生产回退。mock 接线证据不能证明真实模型决策质量或付费供应商验收。

**前置条件：** `2026-10-21-admin-uploads.md` 中已审查的独立平台管理和私有图片上传任务。同一时间只安排一名实现者；主会话分别验证真实 HTTP/浏览器/数据库，并隔离所有测试凭据。测试不需要既有私有用户文件，也不需要真实模型/供应商请求。

## 任务 3 -> 将常见文档接入作为通用 Agent 能力

- 为私有附件添加 PDF、DOCX、XLSX（以及实现成本较低的现有 CSV/TXT）。图片仍限制为 5MiB；文档上限 64MiB，以容纳带媒体的大型工作簿，同时强制实际解压/条目/文本/单元格预算。原始资产保持私有/不变，并保留哈希。不支持的旧格式/宏/扫描件或加密格式具有明确且可操作的状态，绝不伪装为读取成功。
- 复用本地资产授权、生命周期、规范引用和管理状态。不接受浏览器提供的远程 URL/路径，不使用全局公开上传 URL，不在数据库/消息/模型/日志/URL 中存储密码。现有图片保护和总字节预算保持不变。
- 解析使用锁定版本的官方包注册表 PDF.js/Mammoth/ExcelJS，并进行有界 ZIP 预检。仅提取纯文本，绝不运行外部资源/宏/公式；PDF 使用页引用，DOCX 使用段落引用（不虚构页码），XLSX 使用工作表/单元格引用。通过工作线程隔离，提供硬性截止时间/终止、受限环境、输出预算、并发控制和可追踪构建产物。工作线程限制不是完整沙箱；生产环境需要容器资源限制。
- 优先持久化有界分段提取结果（每份文档 1,000,000 字符，声明截断），模型上下文初始放入 2,000 字符预览，并提供可选 `readAttachment` 工具供 Agent 控制分段/范围读取。工具只解析与当前聊天关联且已授权的资产；返回引用/范围/统计。它不决定供应商，也不强制生成表格。长文档/受限/扫描件/密码状态对用户和模型可见；绝不静默声称已完整读取。
- Office 打开密码支持是一项需要单独验证的能力：如果未添加并测试成熟解密实现，则返回文件已锁定状态，并请求提供解密副本。只有经过真实加密夹具测试，才可支持 PDF 临时密码。对于加密/扫描文档，不得静默返回空文本。
- 所有当前/历史/重新生成/审批的模型准备流程使用同一个可信适配器。文档被转为带资产和位置引用的序列化不可信来源文本，不假设供应商 URL/原生 PDF 支持；只有图片要求视觉能力。数据库/UI 中保留原始规范引用。
- UI 允许选择/粘贴实际支持的类型；明确展示上传中/读取中/就绪/截断/错误状态、文档文件名/大小/格式预览，以及重试/移除；不得将未读/失败文档当作就绪发送。保留任务 2 的严格准入/代次锁。
- 先测试：合成多页 PDF、含中文段落/表格的 DOCX、多工作表且包含稀疏/日期/公式缓存单元格的 XLSX；损坏 ZIP/MIME/路径/DTD/条目/解压/输出预算、超时和事件循环响应；明确展示不支持/锁定/扫描状态；无视觉能力模型收到文档文本+引用，绝不收到密码/二进制/私有 URL；保留历史/重新生成/审批路径。主会话提供真实上传->mock 模型的传输证据和 UI 验证，不进行付费调用。

## 任务 4 -> 由 Agent 选择的可选确定性结果表格

- 添加通用 `createResultTable` 工具，接受标题 + 成功 MCP `toolCallId` + 严格 JSON Pointer rowsPath + 可选原始字段路径/展示标签。不接受模型编写的行值/来源 URL。真实成功 MCP 输出成为每个任务的证据台账；历史只从已授权数据库助手工具输出恢复，绝不从客户端消息恢复。失败/待处理/被拒绝输出不能成为证据。工具结果元数据向模型提供调用 ID/结构供其选择。
- 复用 Document `kind:'sheet'`，使用经过校验的 JSON 信封判别字段（`result-table`，版本 1）、来源调用/工具/服务器/时间、chatId、复制的原始行快照、列和视图。继续支持旧 CSV。不使用第二个仅负责标题的模型编造检索行。缺失字段为空，限制明确，不静默伪造/截断行。
- 台账和 UI 来源信息标识“工具返回”，不代表网页验证或法律确定性。只有实际行中精确的 URL 字段可生成安全 HTTP(S) 来源链接；不递归提取偶然出现的文本 URL。
- 右侧面板复用 Workspace + AI SDK 自定义数据 + 现有 shadcn/react-data-grid。显示真实表头、行数、筛选、正确数值排序、列选择、包含原始字段/来源调用/时间的详情、CSV/JSON 导出和重新打开后的持久化。来源值只读；可选用户备注明确独立。结果表格创建是可选行为，不在每次工具调用或出现业务关键词时触发。
- 原子持久化 `data-resultTable` 事件，避免旧类型流式竞态。修复相关现有产物缺陷：真实当前版本属性/只读历史、最新预览、response.ok/脏状态/防抖捕获 ID、不存在对象的 DELETE 保护。视图/备注只允许通过 expectedVersion 事务/CAS 保存；不能经通用文档 POST/edit/update 工具替换证据。
- 可选 `updateResultTable` 使用新的真实台账输出和 expectedVersion，不接受任意 CSV 字符串。读写所有权检查包含绑定聊天。现有 Document 版本和助手工具卡片作为重新打开入口。
- 先测试：台账与行精确一致、无效调用/路径/限制、客户端伪造、持久化历史来源、空数组、不可变证据、筛选/数值/null 排序、CSV 公式防护、并发版本 409、所有者隔离、旧 CSV 兼容，以及同批次流式输出/重新打开。

## 独立最终验证

1. 主会话运行全部现有单元套件 + 新套件、类型检查/lint/差异检查，以及干净源码生产构建/启动（不使用迁移包装命令）；验证解析工作线程确实被追踪，并在生产副本中运行。
2. 真实隔离 PostgreSQL 迁移/幂等性/约束；自有私有文件系统中的原始字节上传/读取/删除，以及角色/Origin/跨聊天检查。
3. 合成文档以带引用的提取文本传给隔离 mock 模型；图片作为有效 OpenAI data URL 传入（严格传输检查，不能只依赖宽松 mock 成功）。
4. 隔离假 MCP 返回带标签的合成行。SDK 工具循环执行调用、需要时的审批/继续、证据捕获，以及 Agent 选择的表格工具；数据库行与工具载荷精确一致。mock 模型只使用确定性测试行为；生产仍保持自主模型工具/技能循环。
5. 真实浏览器验证上传、错误、可选工具审批、右侧表格排序/筛选/详情/导出/重新打开及窄屏布局。捕获截图；不接触真实客户文档/数据。
6. 先独立规格审查，再质量/安全审查；本地提交前修复/复审。主会话集成到主检出目录并重新运行验证。如实报告 mock 与真实覆盖；不笼统宣称与 Manus 产品能力对等。

### 具体审查澄清

- 文档工作线程默认值：同一时间只运行一个解析器（繁忙时拒绝，不使用无界队列）、64MiB 输入、4096 个 ZIP 条目、128MiB 声明及实际解压总量、每个 XML 32MiB/全部 XML 64MiB、300 页 PDF/50 个工作表/100,000 个非空单元格、20s 终止截止时间。每个解析器获得私有临时目录，即使超时也由父进程清理。每个资产文本 1M 字符，初始预览 2k，readAttachment 每次调用 <=16k，每轮模型总计 100k 字符。明确声明截断，限制同样适用于可选读取；被丢弃内容不能暗中读取。使用流式 ExcelJS WorkbookReader 排空媒体，不使用会将嵌入图片提前缓冲的 xlsx.load；ZIP 预检仍计入实际解压媒体。不进行媒体 OCR 或公式执行。
- 首版明确将具有打开密码的加密 PDF/Office 拒绝为已锁定，并请求提供本地解密副本。纯扫描 PDF 返回 no_extractable_text；混合 PDF 标记空白页。本补丁不提供密码输入/解密状态机。新增解析器包版本和 Node 运行时前提必须锁定/记录，并要求生产工作线程冒烟验证。
- 结果台账：最近 20 次成功且符合条件的 MCP 调用，累计 2MiB；明确给出不可用/过大错误，不提供部分事实冒充完整结果。当前调用记录服务端完成元数据；历史复用已持久化完成元数据，否则将 message.createdAt 标注为消息记录时间（绝不用当前时间）。优先使用 `structuredContent`；回退时只解析完整的有界文本 JSON，不对自然语言使用正则提取。行必须为对象数组；严格遵循 JSON Pointer 标准转义/数组规则，并禁止访问原型/非规范路径/越界位置。
- 即使信封损坏或版本未知，结果信封检测仍受保护：通用文档 POST/edit/update 不能降级为 CSV/重写证据。视图/备注只允许通过显式 schema + 事务性 expectedVersion 更新；在锁下确保 createdAt 单调递增，避免同毫秒版本冲突。updateResultTable 刷新工具可后续再做；首版只需证明可选创建/查看/筛选/导出/重新打开。mock 测试包含不生成表格的分支，不能只有固定成功路径。

### 面向 Agent 的来源发现与上下文预算

不要假设协议封装中的 `tool_call_id` 对模型而言是可读字面值。使用有界的面向模型工具结果投影（已安装 AI SDK 的 `toModelOutput`），或可选来源列表能力，使真实成功来源 ID/结构可被发现。在 UI/数据库和台账中保留原生原始工具输出；不替换供应商字段名，也不接受模型编造的行。有界预览必须明确声明其为预览，并包含总行数/字段/调用引用；确定性表格构建仍可访问原始行。在持久化前，通过 `convertToModelMessages(...,{tools})` 或等价机制，为已授权数据库历史复用相同投影。不得将数兆字节原始供应商载荷静默变成无界付费模型提示。额外能力保持可选，不形成自动业务流水线。

文档派生提取存储也必须有配额/数量上限，不能只限制压缩原件大小：大量微小高压缩文档不能通过产生大规模持久化文本绕过配额。计算有界派生字节，或强制同样明确的资产/提取配额。本阶段仍仅支持本地存储；不引入云依赖。
