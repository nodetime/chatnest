# Agent materials and result-artifact completion plan

**User acceptance:** an Agent-centric application, not a scripted business pipeline. The model chooses tools/skills, iteration and optional deliverables. Runtime owns permissions, bounded execution, tool provenance, persistence and UI. Mock MCP/model services exist only in ignored isolated verification fixtures, never as production fallback. Mock wiring evidence is not proof of live model decision quality or paid supplier acceptance.

**Prerequisite:** reviewed independent platform admin and private image upload task in `2026-10-21-admin-uploads.md`. One implementation writer at a time; root separately verifies actual HTTP/browser/DB and isolates all test credentials. No existing private user files or real model/supplier requests are required for testing.

## Task 3 — common document ingestion as generic Agent capabilities

- Add PDF, DOCX, XLSX (also cheap existing CSV/TXT) to private attachments. Keep images 5MiB; document cap64MiB accommodates a large workbook with media, while enforcing actual decompression/entries/text/cell budgets. Original assets remain private/unchanged with hashes. Unsupported legacy/macros/scanned or encrypted formats have explicit actionable states, never fake read-success.
- Reuse local asset authorization, lifecycle, canonical refs and admin status. No browser-supplied remote URL/path, no global public upload URLs, no password in DB/message/model/log/URL. Existing image guards and total-byte budget remain.
- Parsing uses pinned official-registry PDF.js/Mammoth/ExcelJS plus bounded ZIP preflight. Pure text only, external resources/macros/formulas never run; PDF page refs, DOCX paragraph refs (not fictional pages), XLSX sheet/cell refs. Worker isolation with hard deadline/terminate, restricted environment, output budgets, concurrency and traceable build artifact. Worker limits are not a complete sandbox; production container resource limits are required.
- Prefer persisted bounded segment extraction (1,000,000 characters per document, declared truncation) with an initial 2,000-character preview in model context and optional `readAttachment` tool for Agent-controlled segment/range reading. The tool only resolves authorized assets associated with current chat; refs/ranges/statistics are returned. It never decides a supplier or forces a table. Long/limited/scanned/password states are visible to the user and model; never claim full reading silently.
- Office opening-password support is a separate proven capability: if no mature decrypt implementation is added/tested, return locked-file status and request a decrypted copy. PDF ephemeral password can be supported only with actual encrypted fixture tests. No silent empty text for encrypted/scanned documents.
- All current/history/regeneration/approval model preparation uses the same trusted adapter. Documents become serialized untrusted source text with asset and location refs, not vendor URL/native-PDF assumptions; vision capability is required only for images. Preserve original canonical refs in database/UI.
- UI allows selecting/pasting actual supported types; clear upload/reading/ready/truncated/error states, document filename/size/format preview, retry/removal, no sending unread/failed documents as if ready. Strict admission/generation locks from Task2 retained.
- Tests first: synthetic multipage PDF, Chinese paragraphs/table DOCX, multi-sheet sparse/date/formula-cache XLSX; bad ZIP/MIME/path/DTD/entry/inflate/output budget, timeout and event-loop response; unsupported/locked/scanned explicit; nonvision model receives document text+refs and never passwords/binary/private URL; history/regeneration/approval paths preserved. Root actual upload→mock-model wire evidence and UI, no paid calls.

## Task 4 — optional deterministic result tables selected by the Agent

- Add a generic `createResultTable` tool that accepts title + successful MCP `toolCallId` + strict JSON Pointer rowsPath + optional original field paths/display labels. It does not accept model-authored row values/source URLs. Actual successful MCP output becomes a per-task evidence ledger; history restores only from authorized DB assistant tool outputs, never client messages. Failed/pending/denied outputs cannot become evidence. Tool result metadata makes call IDs/structure available for model selection.
- Reuse Document `kind:'sheet'` with a validated JSON envelope discriminator (`result-table`,version1), source call/tool/server/time, chatId, copied original row snapshots, columns and view. Legacy CSV stays supported. No second title-only model invents retrieved rows. Missing fields are empty, limits explicit, no silent fabricated/truncated rows.
- Ledger and UI provenance identify 'tool returned', not web verification or legal certainty. Only exact actual row URL fields may create safe HTTP(S) source links; no recursive extraction of incidental text URLs.
- Right pane reuses Workspace + AI SDK custom data + existing shadcn/react-data-grid. Show real headers, row count, filter, proper numeric sorting, column selection, details including raw fields/source call/time, CSV/JSON export and reopen persistence. Source values read-only; optional user notes clearly separate. Result table creation is optional, not triggered on every tool call or business keyword.
- Atomic persisted `data-resultTable` event avoids old-kind streaming races. Fix related existing artifact bugs: real current-version props/read-only history, latest preview, response.ok/dirty state/debounce captured IDs, nonexistent DELETE guard. Save view/notes only with expectedVersion transaction/CAS; cannot replace evidence via generic document POST/edit/update tools.
- Optional `updateResultTable` uses new actual ledger output plus expectedVersion, not arbitrary CSV strings. Read/write ownership includes bound chat. Existing Document versions and assistant tool cards are reopen entrypoints.
- Tests first: exact ledger↔rows identity, invalid call/path/limits, client forgery, persisted history provenance, empty array, immutable evidence, filter/numeric/null sort, CSV formula protection, concurrent version409, owner isolation, oldCSV compatibility, same-batch streaming/reopen.

### Concrete review clarifications

- Document worker defaults: one parser at a time (reject busy rather than unbounded queue),64MiB input,4096ZIP entries,128MiB declared and actual inflated total,32MiB perXML/64MiB totalXML,300PDF pages/50sheets/100,000nonemptycells,20s terminate deadline. Each parser gets private temporary directory cleaned by parent even on timeout. Text1M chars/asset, initialpreview2k, readAttachment<=16k/call,100k chars total per model round. Truncation is explicit and limits also apply to optional reading; discarded content is not secretly retrievable. Stream ExcelJS WorkbookReader to drain media rather than eager xlsx.load buffering embedded images; ZIP preflight still counts actual inflated media. No media OCR or formula execution.
- First release explicitly rejects opening-password encrypted PDF/Office as locked, requests a locally decrypted copy. Scan-onlyPDF returns no_extractable_text; mixedPDF marks empty pages. No password input/decrypt state machine in this patch. New parser package versions and Node runtime prerequisites must be pinned/documented, production worker smoke required.
- Result ledger: most recent20successfuleligibleMCPcalls, cumulative2MiB, explicit unavailable/too-large errors without partial truth. Currentcalls record server completion metadata; history reuses persisted completion metadata, else message.createdAt is labeled message-recorded time (never now). `structuredContent` preferred; fallback parses entire bounded text JSON only, no prose regex. Rows must be object arrays; strict JSON Pointer standard escapes/arrays and deny prototype/noncanonical/out-of-range access.
- Result envelope detection stays protected even damaged/unknown versions: generic documentPOST/edit/update cannot downgrade toCSV/rewrite evidence. View/notes allowed only by explicit schema+transactional expectedVersion; ensure monotonically increasing createdAt under lock to avoid same-millisecond version collisions. updateResultTable refresh tool may follow later; first proven optionalcreate/view/filter/export/reopen is enough. Mock tests include a no-table branch, not only a fixed happy path.

### Agent-facing source discovery and context budget

Do not assume protocol-envelope `tool_call_id` is a readable literal to the model. Make actual successful source IDs/structure discoverable using a bounded model-facing tool-result projection (`toModelOutput` in installed AI SDK) or an optional source-list capability. Preserve native raw tool output in UI/DB and ledger; do not replace provider field names or accept model-invented rows. A bounded preview must explicitly say it is a preview and include total rows/fields/call reference; original rows remain available to deterministic table construction. Reuse the same projection for authorized DB history via `convertToModelMessages(...,{tools})` or equivalent, before persistence. No multi-megabyte raw vendor payload should silently become an unbounded paid-model prompt. Keep extra capabilities optional, not an automatic business pipeline.

Document derived extraction storage must also have a quota/count bound, not just compressed-original size: many tiny highly-compressed documents must not bypass quotas by producing large persisted text. Account for bounded derived bytes or enforce an equally explicit asset/extraction quota. This remains local storage only; no cloud dependencies in this phase.
