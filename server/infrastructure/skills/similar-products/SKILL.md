# 找相似商品

目标是找到与参照相似的商品，并说明判断依据。搜索相关性不等于外观相似；相似线索也不等于侵权结论。

## 工作方法

1. 先理解参照及用户关心的特征：整体造型、结构比例、图案布局、文字标记或局部设计。已有图片、链接或足够描述就直接推进；缺少参照且会改变检索时再询问。不能只因用户说“调查”就开始泛搜，也不默认转成采购、供应商或工商调研。
2. 按当前工具实际支持的方式召回候选。有图搜才使用图搜；从图片提取外观关键词后文字查询，应明确这是文字召回。先用最有区分度的一组关键词、小批召回用户所需数量，并显式传入数量参数。例如用户找3个候选，第一批取3个，而不是先取默认20个。检查这一批后，只有候选不足、重复或明显不符才针对缺口补查；已有足够候选就进入比较。沿用用户指定的平台、范围及调用次数。图片读取失败或预览受限不代表检索失败：沿原始来源定位图片，不猜字段路径，不重新付费检索弥补展示问题。
3. 用商品编号或规范商品链接去重。查看真实候选图片后再做视觉比较；工具只返回标题、链接或图片加载失败时，保留“信息不足”，不能凭标题、网址、搜索排名编造图像细节。读取候选图片时沿用原始查询的来源和图片字段。
4. 按参照中最有区分度的特征逐项比较，同时给出相似点和差异点。未指定的材质、表面工艺和细节保持未知，不增补为用户条件。结论只评价外观：“哪些特征一致、哪些不同、哪些看不到”。即使图片和详情版式一致，也只描述图片一致；“疑似同源”“疑似同款货源”“同模具”涉及来源关系，不能从外观比较推出。视角遮挡、分辨率和缺少局部图会限制判断。候选之间采用一致口径，不把检索排序分当作相似百分比，不编造量化精度。
5. 结果区分“较相似”“部分相似”“明显不同”和“信息不足”，给出可核查的具体理由。足以回答时停止扩展；候选不足就如实交付已有结果，说明哪项信息会影响判断。

## 交付

多候选的完整比较默认交付一份右侧工作区报告，通过 `createDocument` 提交已完成的正文，`kind` 选择 `text`。聊天用一小段话概括最接近的候选和关键差异，附报告入口；逐候选长列表和比较表留在报告里。用户指定其他交付形式时遵从其选择。

报告先写参照特征、检索范围和总体结论，再按候选分节呈现原始商品链接、可靠来源图片、相似点、差异点、判断与局限。使用清晰的小标题和短列表适配右侧阅读与编辑。商品来源用 Markdown 链接 `[商品标题](原始商品链接)`，候选图用 `![候选主图](原始图片链接)` 展示，用户可以直接看图和打开商品。价格、店铺、主体等未返回字段保持未知，商品原始信息与模型比较判断分开。

原始商品数据可直接从已有查询结果回看。用户要求明细表或表格文件时再创建单独表格，并准确说明实际支持的格式；默认报告包含完成比较所需的信息。涉及维权用途时标注辅助初判，供专业人员复核。
