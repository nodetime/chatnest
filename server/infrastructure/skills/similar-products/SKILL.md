# 相似检索与比较

## 1. 定范围

以用户给的参照和条件为准，先确定比较对象（商品、商家或内容）、要交付的分组，以及数量是上限还是目标。只要同款就不混入相似；找相似或两类都要时，分开列出同款和相似。用户只允许使用已有资料时，读原始结果及其中的主图或原文，不新开搜索、商品查询或翻页。

## 2. 取证据

- **商品：**从 `sourceFile` 取原始记录，以来源调用和原始行定位商品、SKU、主图及链接。同一商品多次出现时，核对哪条来源实际对应所选 SKU 和主图，不用第一条召回自动覆盖其他来源。需要新查时才按工具实际参数查找；上游超限提示不是商品记录。
- **主图：**以原始 `sourceToolCallId` 和 `imagePath` 读取候选图，核对图片、商品与 SKU 对应。用户要求重新看图时，本轮必须看到入表候选的实际图片，拿不到的留作待核对。若用户点名复核某个候选，或要求复核的差异已对应到已有结果中的具体候选，先重看并判组，再按销量截取；不因预计排不上而跳过核对，也不为此强行入表。未要求重新看图时，才可复用能追溯到同一张图、原始行和 SKU 的已核对记录。旧表分类、旧描述和单独的历史元数据不是看图证据。
- **内容：**引用对应原文段落或设计图区域，记录具体重合和差异。图片只能支持可见比较；材质、规格、授权或供货关系按各自来源判断。缺首发时间、权属等依据时，保留为待核查线索，不把相似说成侵权结论。

## 3. 分组与排名

每个候选只归一类。**先检查排除同款的差异，再考虑是否同款；尺寸、结构或销量都不覆盖这一步。**

| 判定 | 放入哪里 |
| --- | --- |
| 关键特征有据，所需规格相符，无影响同款的差异 | 同款 |
| 本体多出、少了或更换标识、印花、配色，或规格有差异，但用途与主要结构仍对应 | 相似，不进同款。图外水印不算本体标识 |
| 关键依据不足、看不清或来源矛盾且影响分组 | 待核对，不进确认排名 |
| 用途或主要特征不相符 | 排除 |

排除官方店按商家身份，不按标题是否出现品牌。按用户指定的对象去重：找商品按商品 ID，找商家按商家标识；统一数字和字符串 ID，不跨查询累加销量。同款不因超过名额而降为相似。需要排名时，按组用原始指标排序，保留并列；优先核对可能排在前面或并列的候选。确认多少交付多少；只声称覆盖已核对的来源，不称全站排名。没有指标留空，不当作 0。

## 4. 保存主表

默认一份主 CSV。商品排名保留分组、商家、商品、来源链接、排序指标和匹配依据；相似比较保留对象、主图或原文、判断、相似点、差异、来源、事实依据和核实状态。表内区分画面所见、SKU 标注和原文事实；只有实际核对且足以支撑本行结论才打 `☑️`，需要另列待核对线索时写清缺口。缺失字段留空，保留真实的 0。

保存前反查「同款」组：若差异栏写了本体多出标识或印花，这行就不能同时标为同款。再检查图与来源对应、分组互斥、去重、名次和数量。用现有通用文件工具保存到 `outputs/`；临时核查留在工作区，说明留在表内。修改已有主表时读当前版本并写回原路径，保留本次范围外的内容。

## 5. 聊天交接

主表已保存且按范围完成时，**只回一句，填入主表中用户所要分组的实际数量，然后结束**。例如：「主表已保存：同款 X 条、相似 Y 条。」不补总数、核对过程、商品、销量、并列、截取原因或文件路径；回复下方的文件卡就是入口。

只有未达到用户要求的最低数量，或关键证据缺失导致请求未完成时，才加一句说明缺口。用户指定的范围、正常名次或未入榜候选不是缺口。主表没保存就直接说明，不用聊天长表冒充交付。
