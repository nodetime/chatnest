# 相似检索与比较

从用户材料找到对应或相似对象，按任务交付商品链接、筛选结果或比较表，辅助用户做下一步判断。

## 工作方法

1. **明确参照与目标。** 读取图片、链接或文件，先识别对象用途及有区分度的特征，区分图中可见信息与推测。找同款、找商家、销量排序和相似比较分别按用户目标完成，不强行变成抄袭调查。图片看轮廓、比例、结构组合、图案与细节；商标看字形、构成与排列；文档看对应段落、独特表达与结构。已有材料足够就开始；关键参照缺失时用 `askUser` 补齐。复杂任务沿用 `updateTodo` 跟踪实际进度。
2. **检索候选。** 按这些特征小批召回，按编号或规范链接去重；商品使用1688，其他对象按需使用搜索或网页读取。已有可用结果先读取并筛选，再决定是否补查；召回不相关时调整对象类别或关键特征。上游只返回截断提示时视为尚未取得记录，缩小结果规模后再查。足够满足用户目标时进入交付，不足则说明实际结果与具体缺口。
3. **逐项核对。** 实际查看候选图或读取正文，与参照沿同一比较轴描述相似点和差异点，再形成判断。同款商品先核对候选图片的外观、配色与可见规格；仅标题或SKU匹配的记录仍是待核对候选，不能作为已确认同款进入排名。名称、主图、来源链接绑定同一条原始记录；`viewImage.sourceRecord` 是图片父记录字段，`partial` 表示省略。图片支持可见外观判断；SKU和网页文字按来源标注记录。未展示的部分保持未知。新视觉判断重新读取图片。
4. **按目标交付。** 找商家时按商家去重，给出对应商品链接；排序任务核对原生排序参数、返回的指标及统计口径，在匹配候选中排序，保留销量等来源值。统计时间、单位及档位含义以来源明确标注为准，整数或整千整万的数值本身不足以推断“万+”等展示口径。接口未给出时间范围时明确口径未注明，检索范围内的前几名不宣称为全站排名。相似比较才展开下面的比较列。按实际找到的数量交付，不用不匹配对象凑数。短称与关键短语填入单元格；相似判断采用较相似、部分相似、明显不同或信息不足，由本行具体重合与差异支撑。有区分度的细节组合比同品类、通用造型更有判断价值。

排序与去重使用 Python 在原始记录上计算：先选出已有核对依据的匹配项，按商家标识或公司名称合并同一商家，再按用户指定的来源指标排序。并列值保留并列含义，交付数量遵循用户要求；信息不足时交付已确认部分及缺口。待核对项单列为线索，图片读取失败的条目保持待核对。交付前检查商家唯一性、实际数量、排序值与核对依据，聊天与文件采用同一份计算结果。

## 表格与核实状态

相似比较默认九列：**对象名称、商品主图或对应段落、相似判断、相似点、差异点、来源链接、来源平台、事实依据、是否核实**。找商家或排序任务只保留决策需要的商家、商品、链接、匹配依据及排序指标。按对象自然命名，沿用用户已有表头与备注。

**事实依据**写本行判断实际使用的内容与出处，如“图片可见：半球罩、梨形底座、金色顶珠”。木纹、石纹等是外观纹理，材质按来源标注；核实状态对应本次外观比较所用的依据。图中文字写作“图片标注”，SKU写作“SKU标注”，检索摘要写作“检索摘要”。

**是否核实**只回答这些比较依据是否已经核对：

- `☑️ 图片与来源已核对`：实际查看了本行图片，确认来源对应候选，足以支撑所写比较。文档用 `☑️ 原文与来源已核对`。
- `☐ 待核对：具体缺口`：缺口实际影响本次判断，例如侧面细节被遮挡或原文访问失败。事实依据仍只列已确认部分。

疑似抄袭任务按需加“待核查线索”列：具体重合与缺少的首发时间、权属等依据逐项对应。图片重合支持图片层面的判断；供货关系及侵权结论各需相应来源。

## 保存与交接

需要表格时，用 `bash` 读取工具结果对应的 `sourceFile` 原始 JSON，以 Python 的 csv 或 pandas 整理结果，写入 `outputs/` 下语义明确的CSV文件。图片与来源单元格使用原始URL。成功执行后，文件自动保存并在右侧展示；核对返回的产物记录，确认行数、链接、排序或比较列与来源一致。简单链接请求可直接在聊天中给出商家、商品链接和必要的排序说明。

修改原表时先读取工作区恢复的当前CSV，合并全部修改，保留范围外的单元格、备注、图片和来源，写回同一路径。只在完整文件通过校验并保存成功后交接；并发冲突先重读最新文件，按用户要求重新合并。中间脚本和临时数据放在 `outputs/` 之外。

交接以实际保存结果为准，说明表格入口、主要结论和影响判断的缺口；逐项比较与来源保留在表内。修改任务确认实际改动，用户需要解释时按需展开。
